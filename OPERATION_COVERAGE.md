# Public C operations and Lean coverage

## Contract and snapshot

Long-term goal: every public mathematical operation has a corresponding proved
mathematical specification. This does **not** require C implementation verification
now. A Lean enclosure theorem, an expression evaluator case, and a C/IEEE refinement
proof are three different deliverables. No row claims C implementation correctness.
Mathlib definitions alone do not count as an operation-specific interval proof.

Inventory baseline: merged main `3975a5e1696e59c337093435ffce0748f074a057` (Lean stack #44–#68 merged, followed by
native #31). The pinned [API symbol inventory](provenance/relgraph-api.json) is the standalone test authority; it records source header blobs and hashes without copying C code. `BasicIntervalOps`
rows were subsequently merged in PR #69 (`4e8a8f4`), beyond that inventory baseline.
Floor/ceiling, monotone endpoint results and conditional hardware addition were
merged in PR #70 (`ee964e6`). Conditional hardware operations through division are merged through PR #73; square root remains separate pending PR #74. All other proved rows refer to merged Lean code. This table includes constructors,
queries and the two infrastructure calls so no public function is silently omitted.
The local test `tests/test_operation_coverage.py` enforces exact header/row coverage.

Global refinement gaps: binary64 encoding, infinities, NaNs, signed zero, subnormals,
overflow/underflow, fenv preservation, compiler behavior, MPFR contracts and actual
C execution are not verified here. Existing directed-rounding theorems assume
outward enclosure for successful results; this milestone adds no FP assumptions.
`QInterval` denotes nonempty finite rational closed intervals over real values.
Its utility operations are not automatically operations on generalized domains.

## Next coherent milestones

1. Establish finite endpoint/set operations (this branch), with exact intersection
   emptiness and controls distinguishing hull from union.
2. Monotone endpoint transport and floor/ceiling are now proved in this branch.
   Nonnegative integer powers remain next; keep domains and endpoint behavior
   separate from continuity.
3. Specify Boolean interval semantics and comparisons, preserving empty-input and
   partial-domain distinctions before evaluator integration.
4. Add transcendental domain/range results in source-grounded groups, then rational
   remainder and rational gcd/lcm specifications. Do not substitute totalized real
   division/log/root definitions for the intended partial relations.
5. Independently refine to C/binary64 when requested. This remains separate from
   graphing v1.0 and does not alter its build, release criteria or hosted CI.

## Source alignment

The existing graphing inventory's C05 entry identifies Tupper §§3.2.10–3.2.14
(monotone sections, negation duality and piecewise monotone examples). The finite
negation/absolute-value results are narrow mathematical building blocks for those
constructions, not a formalization of the full generic source algorithm. The
hull/intersection results are ordinary set bounds, not generalized branch-cut
identity maps or a claim that an interval hull preserves disjoint possibilities.
See [the concordance](THESIS_CONCORDANCE.md) and
[the basic-operations guide](BASIC_OPERATIONS.md) for exact scope and controls.
